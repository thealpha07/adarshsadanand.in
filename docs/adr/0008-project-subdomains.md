# 0008. Project subdomains live in the monorepo as apps

**Status:** Accepted, 2026-10-31

## Context
The M.Tech project (a SEBI CSCRF Cyber Capability Index scoring tool) needs its own address before the tool exists, so the page can be shared with the guide and the review panel and grow as the tool is built.

## Decision
- **Address:** `cci.adarshsadanand.in`, served by a new app at `apps/cci` and a new Worker `as-cci`.
- **Same pipeline as the other sites:**
  - the same Worker-with-assets setup (ADR 0007), with `wrangler.jsonc` and the SPA fallback;
  - the same shared `@site/ui` and `@site/data` packages;
  - the same CI.
- **Accent colour:** amber, `--amber #8a5300` (6.3:1 on white) on light backgrounds and `#e0a84a` on dark ones. Icons are generated by `scripts/make-icons.mjs`.
- **Hidden until launch:**
  - The page carries `noindex`, and `robots.txt` disallows all crawling.
  - It isn't in the main nav.
  - At launch, change both files and decide where to link it from.
- **Routing:** the holding page catches every path. The tool's screens are added later as routes (for example `/assess` and `/report`), so the address people bookmark today keeps working.

## Alternatives not chosen
- **A path such as `adarshsadanand.in/cci`:** this would tie the project's releases to the portfolio's. A separate subdomain can later move to its own repo or backend without breaking links.
- **A separate repository now:** this would duplicate the design system and CI before there is any tool code to justify it. If the tool needs its own server or database, it can move out then; the subdomain stays the same.
- **Linking it from the homepage now:** the page is a holding page. It goes on the homepage once there is something to try.

## Consequences
- There is one more Worker to create in Cloudflare (see docs/setup.md, step 5).
- `SiteKey` now includes `cci`, so `siteUrl("cci")` works from any site.
